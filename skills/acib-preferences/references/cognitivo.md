## 🎨 FORMATOS PREFERIDOS

### **Visual:**

| Formato | Uso | Evidência |
|---------|-----|-----------|
| **Tabelas** | Comparações, status, checklists | ✅ Usou e aprovou hoje |
| **Diagramas ASCII** | Arquiteturas, fluxos | ✅ "Arquiteto de IAs" |
| **Cores/Emojis** | Status, categorias | ✅ 🔴🟡🟢 = Alta/Média/Baixa |
| **Tree view** | Hierarquias, estruturas | ✅ Estrutura de pastas |
| **Cards/Blocos** | Agrupamento visual | ✅ Preferência por separação |

### **Textual:**

| Formato | Uso | Exemplo |
|---------|-----|---------|
| **Bullet points** | Listas acionáveis | Próximos passos |
| **Negrito** | Ênfase em ação | **FAZER:**, **URGENTE:** |
| **Headers curtos** | Seções claras | ### **1. DEPLOY** |
| **Código inline** | Comandos | `pct push 107 ...` |
| **Code blocks** | Scripts completos | ```bash ... ``` |

### **Estrutural:**

```yaml
preferencia_hierarquia:

  - "O que importa AGORA"
```

## 📊 NÍVEIS DE DETALHE

### **Matriz de Contexto:**

| Contexto | Nível | Como Responder | Exemplo |
|----------|-------|----------------|---------|
| **Urgente/Calor** | Mínimo | Só ação + resultado | "Deploy feito. URL: ..." |
| **Rotina/Dia-a-dia** | Padrão | Ação + resultado + próximo passo | "Backup em X. Próximo: Y" |
| **Novo/Desconhecido** | Completo | Explicação + alternativas | Por quê + como + o que mais |
| **Estudo/Profundo** | Profundo | Teoria + prática + refs | Documentação extensa |

### **Triggers Detectados:**

**Quer mínimo:**
- "Rápido", "Só faz", "Manda bala", "Sem enrolação"
- Comandos curtos, sem pergunta

**Quer padrão:**
- Perguntas diretas sobre status
- "E aí?", "Como tá?", "Qual o próximo?"

**Quer completo:**
- "Como funciona?", "Por que?", "Explica"
- "Nunca fiz isso", "Primeira vez"

**Quer profundo:**
- "Documenta", "Cria skill", "Explica direito"
- Contexto acadêmico (faculdade)

## 🔄 PROCESSAMENTO DE INFORMAÇÃO

### **Sequência Observada:**

```
1. ENTRADA
   ↓
2. PATTERN MATCHING RÁPIDO
   "Isso é parecido com...?"
   ↓
3. AÇÃO/VALIDAÇÃO
   "Funciona?" / "Faz sentido?"
   ↓
4. DOCUMENTAÇÃO (se positivo)
   "Registra pra não perder"
   ↓
5. REPETIÇÃO/OTIMIZAÇÃO
   "Da próxima vez faz assim"
```

### **Velocidade de Processamento:**

| Tipo | Velocidade | Exemplo |
|------|------------|---------|
| **Comandos diretos** | ⚡ Instantânea | "Faz backup" → Executa |
| **Padrões reconhecidos** | 🚀 Rápida | "Cores vibrantes" → Aplica #FF6B9D |
| **Novos conceitos** | 🐌 Moderada | Precisa de exemplo prático |
| **Abstrações puras** | 🐢 Lenta | Requer anália concreta |

## 📝 RETENÇÃO E MEMÓRIA

### **Como Fixa Conhecimento:**

1. **Fazendo** (70%) - Principal método
2. **Documentando** (20%) - Registra para consulta
3. **Revisitando** (10%) - Volta a documentos próprios

### **NÃO fixa por:**
- ❌ Leitura passiva
- ❌ Ouvir explicações longas
- ❌ Anotações de outros

### **Padrão de Consulta:**
```
Cria documentação → Salva na ARCA → Consulta quando precisa → Atualiza
```

## 🧩 RESOLUÇÃO DE PROBLEMAS

### **Abordagem:**

```yaml
estilo: "divide_e_conquista_pragmatico"

passos:
  1: "Identifica o problema mais bloqueante"
  2: "Testa solução rápida (5 min)"
  3: "Se falhar, tenta alternativa"
  4: "Se persistir, documenta e pede ajuda/estuda"
  5: "Nunca gasta +30 min em impasse sozinha"
  
preferencia_ferramentas:
  - "logs_imediatos" (tail -f /var/log/...)
  - "testes_rapidos" (curl, ping, ssh)
  - "isolamento" (funciona em partes?)
  - "rollback" (tem backup? restaura)
```

## 🎯 ADAPTAÇÃO RECOMENDADA

### **Para Novos Conceitos:**
1. Começar com **exemplo prático** (não teoria)
2. Mostrar **funcionando** antes de explicar
3. Deixar **tentar** (ambiente seguro/backup)
4. **Documentar** enquanto está fresco
5. Criar **checklist** para próxima vez

### **Para Documentação:**
1. **Tabela** se for comparar
2. **Lista** se for passos
3. **Emoji + cor** se for status
4. **Código** se for comandos
5. **Anália** se for abstrato

### **Para Decisões:**
1. **2-3 opções** quando houver tempo
2. **Recomendação direta** quando urgente
3. **Pros/Cons** se for estratégico
4. **Ação imediata** se pedir "faz"
